# 前端完整审查与 UX 验收报告

审查日期：2026-09-19  
审查对象：梁平县域数字空域与低空运行智能服务平台前端控制台  
审查方式：真实浏览器操作、DOM/可访问性树、截图、E2E 回归、前端类型检查与构建

## 一、结论

当前前端**功能回归通过，但用户体验验收不通过**，不建议直接进入比赛正式演示或商用试点。

- E2E：14/14 通过；
- `npm run typecheck:frontend`：通过；
- `npm run build:frontend`：通过；
- 真实操作仍存在 P0/P1 级体验阻断：权限状态与演示路径不一致、主动作无反馈、导航认知模型不清、地图辅助技术信息过载、版本信息不一致。

## 二、真实操作路径结果

### 1. 登录与启动

首次以生产模式启动时，页面显示登录框，但使用启动时注入的密码返回“用户名或密码错误”。根因是本地持久化 SQLite 账号状态与当前启动环境不一致。对于操作员而言，页面没有说明是凭据问题、环境问题还是服务问题，也没有恢复路径。

**验收：不通过（P0）**

整改：增加启动态健康检查、明确“账号来源/环境/重置方式”，登录失败显示可执行的处理建议；演示启动应使用独立演示数据库或明确的演示账号初始化流程。

### 2. 态势总览

可看到今日任务、告警、地图、规则、飞行器和设施，信息覆盖完整；但首屏操作密度过高，告警区与任务区同时出现同一事件，缺少一个明确的“现在先做什么”主路径。

**验收：部分通过（P1）**

整改：首屏只保留一个主告警入口，其他区域显示引用；将“影响对象、风险、下一步动作”固定为同一信息结构。

### 3. 导航与信息架构

点击“态势 / 任务 / 规则 / 机队”后，页面仍是同一长页面，只改变左侧 active 状态并滚动到对应位置；没有独立视图标题、面包屑或“已定位到”提示。用户容易误以为导航失效。

**验收：不通过（P1）**

整改方向二选一：

1. 改成真正的模块视图切换，并保留当前上下文；或
2. 明确采用单页锚点模式，点击后同步聚焦目标面板、更新 `aria-current`、显示目标模块标题和滚动反馈。

### 4. 任务与航线

任务详情、规则检查、航线结果、回放和导出均可触达。对“需处置”任务，详情主按钮显示“查看待处置告警”，但页面同时显示“暂无待处置告警”，点击后没有可见变化，形成死路。

**验收：不通过（P0）**

整改：无告警时主按钮改为“执行规则检查”或“生成航线”；所有主按钮必须有成功、失败、进行中三种状态，失败时在按钮附近给出原因和下一步。

### 5. 告警处置

同一低电量告警在顶部优先告警和告警中心各出现一次，均有“查看影响”和“标记已处置”，容易造成重复操作。标记已处置没有二次确认、处置理由或成功 Toast/状态播报。

**验收：不通过（P1）**

整改：统一为一个告警卡片组件；危险或不可逆动作增加确认、处置备注和审计反馈；成功后显示“已处置时间、操作人、关联任务”。

### 6. 设施主数据

代码支持设施工作台，但在当前演示/未登录角色状态下，“管理”按钮被权限逻辑隐藏，操作员无法从前端进入设施管理；这会削弱“四维空域单元 + 设施主数据”比赛展示闭环。

**验收：不通过（P0，比赛演示路径）**

整改：保留权限控制，但为比赛演示提供明确的 `dispatcher` 演示账号或只读/演示入口；隐藏按钮时必须显示“当前角色无权限”和切换角色方式，不能静默消失。

### 7. 地图与空间信息

地图视觉上可用，图层开关、缩放、DEM 和坐标读数均有 E2E 覆盖；但可访问性树暴露了数百个道路/OSM 要素为独立 image 节点，导致屏幕阅读器和键盘用户需要穿越大量无关内容。坐标默认显示“坐标 --”，没有提示如何获得坐标。

**验收：不通过（P1）**

整改：底图道路和参考图层默认 `aria-hidden=true`，只把空域单元、设施、飞行器、航线和告警对象暴露为可操作对象；增加地图说明、图层摘要和坐标获取提示。

### 8. 资源状态与飞行器

飞行器电量、位置、海拔和设施容量可见；但飞行器条目没有明确的可点击 affordance，也没有统一的健康状态文本（只显示百分比条），低电量阈值和“可执行动作”未在条目内表达。

**验收：部分通过（P1）**

整改：给飞行器卡片增加“查看详情”按钮、链路状态、任务状态、告警状态和下一步动作；电量使用文本等级+颜色双编码。

### 9. 版本与数据边界

页面左侧显示 `LP-OPS 0.6.0-p0`，追溯条显示引擎 `0.6.1-p0`，版本信息不一致。虽然追溯条声明了“合成演示数据”，但页脚仍使用“SECURE DEMO BUILD · SPRINT 6”，不适合作为正式试点界面。

**验收：不通过（P1）**

整改：版本号只从同一运行时元数据渲染；将“演示 / 封闭试点 / 生产”环境标签置于顶部显著位置，并与数据来源、权限和功能开关联动。

## 三、无障碍与交互门禁

- 已有部分 `aria-label` 和 `aria-live`，但抽屉打开后未明确焦点移入、关闭后未恢复原焦点；
- 地图的语义树过大，影响键盘和读屏；
- 导航 active 状态未使用 `aria-current`；
- 主动作缺少进行中/失败/成功反馈；
- 高风险告警处置缺少确认和可见审计反馈；
- 表单有 `required` 和高度范围，但经纬度、时间窗口先后关系、重复任务编号等错误主要依赖服务端，前端缺少就地校验。

## 四、整改优先级

### P0：必须先修

1. 演示账号/权限与演示路径统一，保证任务检查、航线、设施工作台可从前端完成；
2. 修复“查看待处置告警”无告警时的死按钮；
3. 所有主动作增加进行中、成功、失败反馈；
4. 统一版本号和环境标识；
5. 登录失败提供可执行恢复信息。

### P1：验收前必须修

1. 重构导航为清晰的模块视图或可感知锚点导航；
2. 合并重复告警卡片，补确认、备注和审计结果；
3. 降低地图无障碍树噪声，仅暴露业务对象；
4. 抽屉焦点管理、Escape 关闭、关闭后焦点恢复；
5. 增加经纬度、时间窗口和重复编号的前端校验；
6. 飞行器卡片补充链路/任务/告警状态和明确详情入口。

## 五、复验标准

整改后至少重新执行：

```powershell
npm run typecheck:frontend
npm run build:frontend
npm run test:e2e
```

并新增人工验收脚本：

1. 以演示账号完成登录→选任务→检查→航线→告警→重规划→人工确认→回放；
2. 以 observer 角色验证只读权限，并能看到权限提示；
3. 键盘 Tab 完成导航、抽屉打开/关闭、告警确认和表单提交；
4. 屏幕阅读器不再遍历数百个底图道路节点；
5. 首屏任何 P0 告警都能在两步内到达下一项可执行动作。
