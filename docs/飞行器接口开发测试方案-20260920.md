# 飞行器接口开发测试方案

> 项目：梁平低空运行基础底座平台  
> 版本：v1.0  
> 日期：2026-09-20  
> 适用范围：飞行器/机队系统向平台上报遥测、接收任务关联状态、触发告警与回放验证。  
> 数据边界：当前联调默认使用公开参考 / 合成演示数据，不代表真实授权空域、真实飞行许可或权威测绘边界。

## 1. 目标与原则

### 1.1 目标

建立一套可从“模拟器”平滑切换到“真实飞行器适配器”的接口方案，保证：

1. 飞行器身份、任务和飞行会话可追溯；
2. 遥测数据格式统一、可校验、可审计；
3. 低电量、链路中断、暂停等运行风险能被及时识别并形成事件；
4. 地图、任务卡、时间线和回放使用同一份标准化数据；
5. 设备接入失败、重复上报、乱序、断网恢复等异常可验证、可处置；
6. 比赛演示、封闭试点、正式商业交付分层验收，不把演示能力表述为真实飞控能力。

### 1.2 设计原则

- **平台不直接控制飞控**：当前接口只做数据接入、状态同步、告警建议与审计，不下发起飞、返航、改航等飞控指令。
- **先标准化，再适配设备**：真实厂商协议必须通过适配器转换为平台标准遥测模型。
- **时间和来源可追溯**：每条数据保留设备时间、平台接收时间、来源类型、任务和会话关联。
- **幂等与可恢复**：重复包不重复产生业务副作用；短时断网恢复后可补传或标记缺口。
- **最小权限与默认拒绝**：设备只允许上报自己的数据，运营人员通过业务角色处理任务和事件。
- **可观测优先**：接口返回明确错误码，服务保留请求计数、审计记录、会话和轨迹样本。

## 2. 当前平台能力盘点

### 2.1 已有接口与代码位置

| 能力 | 当前接口/模块 | 现状 |
|---|---|---|
| 设备清单 | `GET /api/vehicles` | 已有，返回飞行器位置、电量、状态等字段 |
| 任务详情 | `GET /api/missions/{id}` | 已有，可关联飞行器、航线、检查结果和飞行会话 |
| 启动演示飞行 | `POST /api/missions/{id}/flight/start` | 已有，仅用于演示/模拟 |
| 演示推进 | `POST /api/missions/{id}/flight/tick` | 已有，生成合成遥测和轨迹 |
| 暂停/恢复/停止 | `POST /api/missions/{id}/flight/{pause|resume|stop}` | 已有，受调度员/管理员角色保护 |
| 遥测写入 | `POST /api/missions/{id}/telemetry` | 已有，统一进入 `normalize_telemetry()` |
| 当前遥测与轨迹 | `GET /api/missions/{id}/telemetry` | 已有，支持 JSON、CSV、GeoJSON 导出 |
| 飞行会话 | `GET /api/missions/{id}/flight` | 已有，返回会话状态和最新遥测 |
| 运行事件 | `GET /api/missions/{id}/events` | 已有，支持 `open/resolved` 查询 |
| 事件处置 | `POST /api/events/{id}/resolve` | 已有，形成审计日志 |
| 遥测归一化 | `backend/telemetry.py` | 已有经纬度、高度、速度、航向、电量、链路、状态校验 |
| 轨迹留存 | `telemetry_samples` | 已有按任务/会话/序号留存 |
| 运行告警 | `runtime_alerts()` | 已有低电量、链路质量下降、暂停状态告警 |

### 2.2 当前明确边界

- 当前没有真实厂商 SDK、机载链路、Remote ID、蜂窝/专网 MQTT 或飞控指令通道的实机验证。
- 当前 `POST /api/missions/{id}/telemetry` 是平台内部/受控联调入口，不应直接暴露给公网飞行器。
- 当前遥测接入以任务 ID 为主键；正式设备接入还需要设备身份、消息 ID、幂等键和权限绑定。
- 当前告警是建议与审计，不会自动触发返航、降高或改航。
- 当前航线规划、风险判断和地图表达仍属于平台业务能力，不能替代适航、空域审批或厂商飞控安全机制。

## 3. 总体接入架构

```text
飞行器/厂商云/机队系统
        │  厂商协议（SDK、HTTPS、MQTT、WebSocket 等）
        ▼
设备适配器 Adapter
  - 身份映射
  - 协议转换
  - 时间/坐标/单位归一化
  - 重试与断线补传
        ▼
接入网关 Gateway
  - TLS / Token / 签名
  - 限流
  - 请求追踪
  - 设备权限校验
        ▼
平台标准遥测服务
  - normalize_telemetry()
  - 任务/会话关联
  - telemetry_samples 留存
  - runtime_alerts()
        ├── 地图与四维态势
        ├── 任务/飞行器状态卡
        ├── 事件处置与审计
        └── 轨迹回放与 CSV/GeoJSON 导出
```

### 3.1 推荐接入路径

1. **比赛演示**：使用内置 simulator，调用现有 `flight/start`、`flight/tick`、`telemetry` 入口。
2. **封闭试点**：先部署设备适配器，由适配器调用平台内网遥测入口；一台设备对应一个平台设备 ID 和一个任务会话。
3. **正式商业交付**：在 Caddy/Nginx 或专用 API Gateway 后提供设备专用入口，启用 mTLS/签名、设备证书轮换、消息幂等、监控、告警、备份和现场恢复演练。

## 4. 平台标准数据契约

### 4.1 设备身份模型（建议新增）

正式接入建议将设备身份与 `vehicles.id` 分离，增加以下字段或独立表：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `vehicle_id` | string | 是 | 平台飞行器 ID，例如 `UAV-LP-001` |
| `provider` | string | 是 | 厂商/系统标识 |
| `provider_vehicle_id` | string | 是 | 厂商侧设备 ID |
| `device_serial` | string | 否 | 设备序列号，需脱敏展示 |
| `protocol` | enum | 是 | `https` / `mqtt` / `websocket` / `sdk` |
| `credential_ref` | string | 是 | 凭据引用，不存明文密钥 |
| `enabled` | bool | 是 | 是否允许上报 |
| `last_seen_at` | datetime | 否 | 最近接收时间 |
| `data_boundary` | string | 是 | `synthetic_demo` / `pilot` / `authorized_live` |

### 4.2 标准遥测载荷

```json
{
  "message_id": "msg-20260920-000001",
  "vehicle_id": "UAV-LP-001",
  "mission_id": "MS-20260915-001",
  "session_id": "optional-provider-session-id",
  "timestamp": "2026-09-20T03:30:15.200Z",
  "longitude": 107.74812,
  "latitude": 30.64231,
  "altitude": 120.0,
  "speed": 12.5,
  "heading": 86.0,
  "battery": 78.5,
  "link_quality": 92.0,
  "status": "airborne",
  "source": "device",
  "provider": "demo-adapter",
  "coordinate_system": "WGS84",
  "altitude_reference": "MSL",
  "sequence": 1042
}
```

`status` 当前允许：`ready`、`airborne`、`paused`、`completed`、`lost_link`、`landed`。

### 4.3 字段校验规则

- 经度：105–110；纬度：28–32；用于梁平演示范围的基础输入校验，正式部署应按项目区域配置。
- 高度：0–1200 m；单位统一为米。
- 速度：0–150 m/s；航向：0–360°。
- 电量、链路质量：0–100。
- `timestamp` 必须为 ISO-8601；服务端统一转 UTC。
- 坐标系统和高度基准必须显式传入或由适配器配置，不允许静默混用。
- 不接受未知状态、NaN、Infinity、空 JSON 或超大载荷。
- 设备上报的 `vehicle_id` 必须已登记且启用；任务必须存在且允许关联该设备。

## 5. 接口设计

### 5.1 当前可复用接口

#### 上报遥测

`POST /api/missions/{mission_id}/telemetry`

- 认证：当前受平台角色保护；正式设备入口改为设备 Token/mTLS/签名。
- 成功：`200`，返回 `session_id`、任务状态和标准化 `telemetry`。
- 参数错误：`422 INVALID_TELEMETRY` / `INVALID_TIMESTAMP` / `INVALID_STATUS`。
- 任务不存在：`404 MISSION_NOT_FOUND`。
- 未授权：`401/403`。
- 服务异常：`500 INTERNAL_ERROR`，调用方应重试但必须遵守退避策略。

#### 查询最新遥测和轨迹

`GET /api/missions/{mission_id}/telemetry?format=json|csv|geojson`

- JSON：当前会话、最新遥测、轨迹点。
- CSV：用于测试、分析、问题复盘。
- GeoJSON：用于地图回放和外部 GIS 检查。

### 5.2 正式设备入口建议

建议新增版本化接口，不破坏现有演示接口：

| 接口 | 用途 |
|---|---|
| `POST /api/v1/device/telemetry` | 设备按消息粒度上报，载荷含 `vehicle_id/mission_id/message_id` |
| `POST /api/v1/device/telemetry/batch` | 断线恢复后批量补传，按 `sequence` 排序处理 |
| `POST /api/v1/device/heartbeat` | 仅更新在线状态和最近连接时间，不改变飞行轨迹 |
| `GET /api/v1/device/config` | 获取已授权的上报频率、字段版本和时间偏差阈值 |
| `POST /api/v1/device/ack` | 仅用于确认平台已接收数据，不代表飞控执行确认 |
| `GET /api/v1/device/{vehicle_id}/health` | 设备接入健康、最近上报、丢包和错误统计 |

### 5.3 幂等、乱序与重试

- `message_id` 全局唯一；相同 `vehicle_id + message_id` 重复包返回成功但不重复写入副作用。
- `sequence` 用于识别乱序和缺包；允许迟到窗口，例如 5 分钟，超窗数据进入审计但不覆盖最新状态。
- 网络错误、`408/429/5xx` 使用指数退避：1s、2s、4s、8s，最多 5 次。
- `4xx` 参数或权限错误不自动重试，需修正后再发。
- 批量补传必须保持单设备、单任务、单会话边界，避免跨设备混包。

## 6. 设备适配器开发方案

### 6.1 适配器职责

1. 与厂商 SDK、云端 API 或机载链路建立连接；
2. 将厂商字段映射到标准遥测字段；
3. 做单位换算、坐标系转换、时间校正和状态映射；
4. 增加 `message_id`、`sequence`、`provider`、`source`；
5. 实现心跳、重连、补传、限流和本地短队列；
6. 不在适配器中复制平台告警规则，告警统一由平台判定。

### 6.2 建议代码结构

```text
integrations/
  adapters/
    base.py              # Adapter 接口、生命周期和错误模型
    simulator.py         # 现有合成演示适配器
    <provider_name>.py   # 厂商适配器
  mappings/
    <provider_name>.json # 字段、单位、状态映射
  transport/
    https_client.py
    mqtt_client.py
  fixtures/
    <provider_name>/     # 脱敏报文样本
```

### 6.3 适配器最小接口

```python
class AircraftAdapter:
    def connect(self) -> None: ...
    def close(self) -> None: ...
    def poll(self) -> list[dict]: ...
    def normalize(self, provider_payload: dict) -> dict: ...
    def health(self) -> dict: ...
```

适配器输出必须再次经过平台 `normalize_telemetry()`，不能绕过平台校验直接写数据库。

## 7. 开发分阶段计划

### Sprint 1：契约冻结与模拟联调（1–2 天）

- 冻结标准遥测字段、状态枚举、错误码和数据边界字段；
- 为现有 `telemetry` 入口补充 `message_id/vehicle_id/sequence` 兼容策略；
- 编写 OpenAPI 或等价接口文档；
- 完成 simulator adapter 和 100 条固定报文 fixture；
- 验证地图、任务卡、事件、轨迹导出链路。

**出口标准**：标准报文可连续上报 10 分钟，地图位置、飞行高度、电量、链路和轨迹一致。

### Sprint 2：设备身份与可靠性（2–3 天）

- 增加设备注册、启停、凭据引用和任务绑定校验；
- 实现幂等、乱序、批量补传、重试和断线恢复；
- 增加设备健康接口和接入指标；
- 增加数据保留、错误报文隔离和审计字段。

**出口标准**：重复包不重复落库；断网 60 秒后补传可恢复，轨迹顺序和最终状态正确。

### Sprint 3：厂商适配器（按实际厂商排期）

- 选择一个有授权、可提供脱敏报文或 SDK 的厂商；
- 依据真实字段制作映射表和 fixture；
- 完成沙箱/测试环境联调，再进入封闭试点；
- 明确厂商状态与平台状态的映射差异。

**出口标准**：授权设备能稳定上报，关键字段映射有样本、有日志、有回放证据。

### Sprint 4：生产化接入（现场条件满足后）

- 部署 TLS/mTLS、网关限流、密钥轮换和告警；
- 接入 PostgreSQL/PostGIS、监控、备份与恢复；
- 做 24 小时长稳、重启、升级、恢复演练；
- 形成设备接入验收单和上线回滚方案。

## 8. 测试策略

### 8.1 测试分层

| 层级 | 目标 | 主要工具/证据 |
|---|---|---|
| 单元测试 | 字段校验、状态映射、告警判定、时间转换 | `python -m unittest` |
| 契约测试 | 请求/响应、错误码、兼容性 | 固定 JSON fixture + HTTP harness |
| 集成测试 | API、数据库、任务/会话/轨迹联动 | SQLite 隔离库、PostgreSQL 测试库 |
| 可靠性测试 | 重试、幂等、乱序、断线补传 | 故障注入脚本 |
| 安全测试 | 认证、权限、重放、限流、输入攻击 | API 安全用例、日志审计 |
| 前端回归 | 地图、状态卡、时间线、回放数据一致性 | Playwright Core/Map E2E |
| 性能测试 | 吞吐、延迟、资源占用 | `scripts/load-smoke.py`、基准脚本 |
| 现场验收 | 实际链路和授权数据边界 | 现场日志、录像、验收单 |

### 8.2 核心测试矩阵

#### A. 正常链路

1. 设备注册/启用后上报一条有效遥测；
2. 首条遥测自动创建或关联飞行会话；
3. 连续 100 条遥测更新飞行器位置和高度；
4. 地图显示当前位置，轨迹点按序连接；
5. 任务详情、飞行器卡、回放和导出结果一致；
6. `completed/landed` 后任务和设备状态正确收敛。

#### B. 参数与数据质量

- 缺少经纬度、高度、电量；
- 经纬度、高度、速度、航向超界；
- 无效 ISO 时间、无时区时间、未来时间、过旧时间；
- 未知状态、NaN、Infinity、超大 JSON；
- 坐标系/高度基准缺失或不匹配；
- 设备 ID、任务 ID 不存在或未授权。

#### C. 可靠性与一致性

- 重复 `message_id`；
- 同一设备乱序 sequence；
- 5 分钟内迟到包、超窗迟到包；
- 429、5xx、连接中断后的重试；
- 批量补传中间一条坏包；
- 服务重启后继续上报；
- 同一任务同时存在两个设备上报。

#### D. 运行风险

- 电量 `20%` 触发低电量告警；
- 链路质量 `<30` 触发链路风险，`<10` 或 `lost_link` 进入离线语义；
- `paused` 触发需人工确认；
- 告警重复上报不产生重复开放事件；
- 事件处置后再次出现风险应重新形成开放事件或按策略升级。

#### E. 安全与权限

- 未登录调用设备写入接口；
- 调度员、管理员、只读角色边界；
- 设备 A 写入设备 B 或不属于本任务的数据；
- 重放旧 token、错误签名、过期时间戳；
- 频率超限、并发突发和大包攻击；
- 日志中不得出现明文密钥和完整敏感凭据。

| 编号 | 用例 | 预期 |
|---|---|---|
| AIR-001 | 有效遥测写入 | 200，返回标准化数据并落库 |

## 9. 故障注入与阻断处理

| 故障 | 识别信号 | 处置 | 是否阻断上线 |
|---|---|---|---:|
| 设备认证失败 | 401/403、无有效会话 | 停止重试，核对设备注册和凭据 | 是 |
| 参数持续非法 | 422 比例上升 | 隔离设备，保留原报文摘要，修复映射 | 是 |
| 时间漂移 | 超过配置阈值 | 校时或标记不可信，禁止用于时间冲突判定 | 是 |
| 链路中断 | heartbeat 超时 / `lost_link` | 生成事件，地图标记离线；不自动控制飞行器 | 试点前是 |
| 重复/乱序严重 | sequence 缺口或重复率超阈值 | 检查设备缓存和适配器队列 | 视比例 |
| 服务不可用 | 5xx、健康检查失败 | 网关熔断、切换备用实例、补传 | 是 |
| 数据库写入失败 | 事务错误 | 暂存队列、告警、恢复后重放 | 是 |
| 地图不更新 | API 成功但 UI 不变 | 检查状态订阅、刷新策略和前端回归 | 比赛演示是 |
| 真实授权边界不清 | 来源或授权字段缺失 | 降级为合成/公开参考语义，禁止上线宣称 | 是 |

### 9.1 阻断规则

出现以下任一情况，停止“真实设备已接入”结论，只能报告为演示或受控联调：

- 无设备身份绑定或无法证明数据来源；
- 未通过认证/权限/重放测试；
- 关键遥测字段丢失或单位、坐标、高度基准不明；
- 断线恢复、重复包、乱序处理未验证；
- 低电量/链路告警不能稳定生成并处置；
- 前端地图、任务卡、轨迹回放与接口数据不一致；
- 未完成备份恢复、长稳或现场授权证据。

## 10. 验收标准

### 10.1 比赛演示验收

- 固定演示报文可一键启动；
- 1366×768 下地图、飞行器位置、高度、时间轴和状态清晰；
- 主航线、备用航线、实际轨迹和风险状态可区分；
- 页面始终显示“公开参考 / 合成演示数据”；
- 可展示一次低电量或链路异常，以及人工处置闭环；
- 不把模拟遥测描述为真实授权飞行。

### 10.2 封闭试点验收

- 至少 1 台经授权设备连续上报 8 小时；
- 上报成功率、重复率、乱序率、延迟和丢包有统计；
- 断线恢复、服务重启、数据库恢复均有记录；
- 设备、任务、会话、轨迹、告警、审计可关联查询；
- 现场人员有操作手册、回滚方案和联系人。

### 10.3 正式商业交付验收

- 设备证书/密钥轮换、网关限流、监控和告警已上线；
- PostgreSQL/PostGIS、备份恢复、升级回滚和 24 小时长稳通过；
- 真实数据授权、坐标/高程基准、厂商协议和服务等级有书面证据；
- 飞控安全责任边界、人工处置流程和应急联系人已签署；
- 通过 `npm run verify:all`、后端单测、Core/Map E2E 和现场验收单。

## 12. 本方案的下一步执行顺序

1. 先冻结标准遥测契约和错误码；
2. 在现有接口上增加兼容的 `message_id/vehicle_id/sequence` 处理；
3. 以 simulator adapter 完成 AIR-001～AIR-015 自动化测试；
4. 再选定一个有授权的厂商协议制作真实 adapter；
5. 通过沙箱和封闭试点验收后，才讨论生产网关和真实数据接入。

> 结论：当前平台已经具备“模拟器/受控联调”的遥测接入基础，但尚不应宣称已完成真实飞行器商业接入。真实接入的关键不在于增加一个 POST 接口，而在于设备身份、协议适配、数据质量、可靠性、安全、审计和现场证据形成闭环。
