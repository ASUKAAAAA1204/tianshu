# 二维地图板块目标、成熟产品对比与调整方案

日期：2026-10-16  
范围：梁平低空运行平台的二维运行地图板块；不包含决赛三维建模专项。

## 1. 结论摘要

二维地图板块应定位为“任务与运行对象的空间态势工作区”，不是底图展示页，也不是飞行控制台。它负责将任务、航线、飞行器、空域/限制区、设施、风险与时间上下文放在同一空间语境中，帮助值守人员发现问题、定位对象、查看依据并转到相应业务动作。

当前实现已经使用本地 MapLibre GL JS，并具备合成任务数据、主/备/实际航线、空间要素、状态对象、图层/高度筛选、缩放拖动、对象点击、任务焦点和数据边界声明。它是可运行的二维演示底座，但当前视觉与交互还不能按成熟运行产品的标准验收：1366×768截图中地图只占主工作区左侧约一半，地图纵向内容被图层和设施管理内容拉长，任务列表与地图争夺首屏空间；航线与对象标签存在聚集和遮挡；“地形参考”控件易被理解为真实地形，而现有地图并未显示可追溯DEM；页面没有地图内的任务时间轴，已有的是任务事件/审计时间线，不应误称为时间维度地图表达。

调整方向：先收敛为“任务聚焦地图 + 右侧对象/任务详情 + 左侧轻量图层 + 地图底部时间控制与图例”的单一工作区；先消除拥挤、建立对象选择反馈、补齐来源/时间语义，再扩展真实底图与DEM。不要在此阶段承诺真实授权空域、真实飞行许可、权威测绘边界、建筑碰撞或AI航路优化。

## 2. 板块目标、职责与边界

### 2.1 产品目标

1. 让值守人员在首屏快速回答：当前关注哪个任务、飞行器在哪里、计划与实际航迹如何、对象处于什么状态、是否有待人工确认的风险。
2. 用空间位置、相对高度、有效时间和运行状态组织信息；缺少数据时明确展示“未知/未接入”，不能用装饰表达填补。
3. 为任务检查、航线查看、事件处置和设施查看提供空间入口；地图是业务上下文，不替代规则判定、审批或飞控系统。
4. 在演示阶段可离线运行、可复现；合成数据与公开参考数据可追溯、可辨识，演示结果不冒充生产授权数据。

### 2.2 应承担的职责

| 职责 | 地图应提供 | 不应越界为 |
|---|---|---|
| 态势表达 | 展示任务相关对象、范围、航线、状态、风险和数据时间 | 全区要素铺满的静态大屏 |
| 空间定位 | 拖动、缩放、任务聚焦、对象选择、坐标/比例尺/方向提示 | 权威测绘或法定空域边界声明 |
| 运行上下文 | 航线版本、计划高度、任务窗口、告警发生时间、数据更新时间 | 仅靠颜色推断业务状态 |
| 业务入口 | 选择对象后打开详情、任务操作或规则结果 | 地图直接下发飞控命令或自动批准任务 |
| 数据可信 | 显示来源、数据边界、时间戳、缺失/过期状态 | 把公开参考/合成数据包装成实时实测数据 |

### 2.3 本项目二维板块功能范围

**P0 核心功能**

- 任务聚焦视图：以被选任务的起终点、航线、相关空域/限制区和邻近设施决定初始范围；保留“返回任务范围/全域”操作。
- 航线语义：主航线、备用航线、实际轨迹、风险航段使用不同颜色、线型、宽度和方向箭头；起终点明确标记；选中航线强化显示，非选中路线降权。
- 对象状态：飞行器至少表达运行/待命/需确认/低电量/失联/已完成；不可仅靠色相，需图标形态、文字状态或详情辅助。
- 图层控制：任务航线、飞行器、空域/限制区、设施、风险/障碍物；图层名称对应实际数据，控件显示启用状态与对象数量/数据状态。
- 对象交互：地图平移、滚轮缩放、按钮缩放、复位；点选飞行器/空间要素后显示选中态和明确详情，不因点击地图空白而误触任务动作。
- 可读性：默认只显示当前任务附近要素；标签按优先级避让；拥挤时隐藏次要标签、聚合或在侧栏列表呈现，不允许标签相互覆盖。
- 数据声明：持续可见“公开参考 / 合成演示数据”及“非真实授权空域、真实飞行许可或权威测绘边界”的边界说明。

**P1 运行可解释性**

- 地图角落显示比例尺、北向、坐标系/坐标提示、当前缩放层级；显示空间数据来源与更新时间。
- 当前任务时间窗以地图底部时间带表达；临时限制区展示有效起止时间；告警事件可定位到发生时刻，并可由事件跳转至地图对象。
- 选中飞行器时呈现高度、状态、电量、遥测/模拟时间；高度层筛选影响对象集合，但不得将二维筛选宣称为三维高度剖面。
- 航线旁或详情中展示距离、预计时长、电量估算、分段高度/风险依据（字段无数据时明确标为未提供）。
- 首次加载、无任务、无图层、数据过期、地图引擎失败、接口失败等状态均有明确反馈和可恢复动作。

**P2 数据与能力扩展**

- 接入经授权或许可合规的矢量底图、DEM、建筑/设施数据，分别登记来源、许可、版本、采集/更新时间和覆盖范围。
- 在完成数据审计后增加地形净空、建筑约束可视化；真实建筑碰撞校核应由规则/路径分析服务给出可复核结果，地图只负责呈现依据。
- MapLibre 继续承担二维运行地图；Cesium 三维演示地图作为独立的演示/分析工作区，避免将三维能力描述成二维地图已有功能。

### 2.4 当前不在二维地图承诺范围

- 实时接入的权威空域、真实飞行许可、生产级飞行器遥测或飞控操作。
- 当前“地形参考”开关对应真实DEM的承诺：核验到的是合成/示意实现，没有完成可追溯DEM数据源接入。
- 建筑物三维模型、真实建筑碰撞、可信离地净空、AI模型自动规划。
- 以现有审计/事件时间线替代地图时间轴。二者语义不同：前者记录业务变更，后者表达任务/限制/告警的空间有效时间。

## 3. 当前实现核对

### 3.1 已具备（代码/入口核验）

| 能力 | 当前实现证据 | 客观状态 |
|---|---|---|
| 二维地图引擎 | 本地 vendor MapLibre GL JS；`frontend/adapters/maplibre-adapter.js` | 已嵌入，地图运行态截图存在 |
| 合成底图/空间数据 | MapLibre 离线 style、GeoJSON 源和本地空间对象渲染 | 是离线演示底图，不是已接入的真实地理底图 |
| 航线 | 主航线、备用航线、实际轨迹和风险航段图层/样式 | 已表达；需继续改善屏幕占比和选择突出层级 |
| 空间对象 | 空域单元/限制区面、设施点、风险点及对象点击 | 已表达；对象语义与标签密度仍需改善 |
| 飞行器与高度筛选 | 飞行器符号、状态/高度数据，高度区间筛选 | 有基础交互；不是高度剖面或3D高度层 |
| 地图操作 | MapLibre 平移/缩放，缩放按钮/复位，高度和图层筛选 | 已有基础操作；应补真实截图和完整状态验收 |
| 坐标反馈 | MapLibre `mousemove` 更新经纬度 | 有经纬度读数；当前需核实其是否在首屏可见 |
| 数据边界 | 地图底部公开参考/合成演示声明 | 已显示，但首屏可读性和持续可见性需优化 |
| 任务/审计时间线 | 任务 timeline API 在结果区显示业务记录 | 是事件/审计时间线，不是地图底部运行时间轴 |

### 3.2 截图验收发现

依据 `test-results/maplibre-1366x768.png`：

1. 首屏布局为“顶部指标 + 左地图/右任务列表”两列；地图宽度约占主工作区一半，核心路线和对象较小，地图难成为页面主工作区。
2. 地图卡片后续继续包含图层、设施清单、设施主数据管理表单。地图可视区域被同卡片的管理工作流拉长，运行地图与主数据维护职责混在一起。
3. 任务列表显示多条相同的 `B3B4 API smoke` 测试任务，视觉上像正式业务任务；这是测试/演示数据隔离与演示数据集治理问题，不应靠视觉隐藏。
4. 航线集中在地图中心附近；要素边界及设施/风险标签与主航线发生靠近/遮挡，标签面积相对地图本体偏大。现有手工限量 callout 只能减少标签数量，并不等价于碰撞检测与动态避让。
5. 地图顶部提供高度筛选和“地形参考”，但地图中没有清晰可读的高度剖面，也没有证据显示开关加载了真实DEM；需重命名为“合成地形示意（演示）”或在真正接入DEM前禁用并解释。
6. 地图内图例存在，但空间面、限制区、设施点、风险点、飞行器状态的符号映射不够完整；颜色不能单独承载状态语义。
7. 任务窗口字段和审计事件时间线存在，但当前截图没有地图底部时间带；“四维态势图”标题容易超出当前可视能力。

结论：当前是“MapLibre 离线二维态势原型”，不是已经达到商业运行中心可用性的地图工作台。之前的嵌入复核只证明开源引擎与基本运行链路，不证明完整地图UX合格。

## 4. 成熟产品对比

对比对象选择依据：DJI FlightHub 2 是无人机运营管理平台；QGroundControl 是成熟的任务/航线规划工具；ArcGIS Mission 是成熟的地理任务协同产品。三者分别覆盖运行态势、航线编辑和地图任务协作，不能简单以单一产品覆盖本项目全部目标。

### 4.1 逐项对比

| 维度 | 本项目当前 | DJI FlightHub 2 | QGroundControl Plan View | ArcGIS Mission | 对本项目启示 |
|---|---|---|---|---|---|
| 产品定位 | 低空运行底座离线原型；数据合成演示 | 无人机管理云平台，强调远程管理、任务规划、作业数据与开放集成 | 面向飞行任务的地面站规划/上传工作流 | 面向组织/团队的地理任务协作，有 Manager、Responder 等角色 | 不要照搬单一UI；地图主流程应围绕“选任务—看航线/约束—检查—处置/记录”组织 |
| 首屏信息 | 四指标、地图、任务卡片并列；管理面板向下堆叠 | 官方资料强调一站式管理及云端远控、航线、数据分析、自动作业、集成；具体页面细节不作为本次结论 | 进入 Plan View 即服务于计划编辑，计划信息、工具、地图和高度/任务信息有明确位置 | 新建任务即配置地图、能力和上下文数据，之后由成员协作执行 | 本项目应让当前任务和空间上下文高于通用指标；设施主数据迁离运行地图 |
| 地图主次 | 地图占工作区左列，任务列表占右列；核心航线不够突出 | 以运营任务与无人机/作业数据为中心；产品能力面向运营闭环 | 地图是任务计划主工作面，任务节点和航迹具有主视觉 | 地图作为任务上下文和协同信息载体 | 首屏以选中任务地图为核心；非地图业务通过右侧详情承接 |
| 航线呈现 | 主/备/实际/风险线均有代码表达；实际展示尺度偏小 | 支持多类型航线/作业规划（官方产品页层面）；不据此推断具体路径编辑手势 | 航点编号、路径线和方向箭头；可选择/拖动航点，配合任务项编辑 | 任务地图承载任务上下文，非专用航线规划器 | 借鉴QGC明确航线节点/方向/被选状态；避免把三类路线压成相似视觉权重 |
| 航线编辑逻辑 | 任务创建通过表单给起终点/高度/时间；地图未形成完整的节点编辑工作流 | 官方称支持智能任务规划和多场景航线；硬件/平台生态与本项目不同 | 选择航点工具后在地图点击添加，选择或拖动已有航点，右侧树编辑任务项；有清空/打开/保存/上传等计划状态 | 创建/配置任务后由团队成员在关联地图协作 | 若本项目进入地图编辑，应独立明确“选择/平移/编辑航线”模式、保存草稿/未保存提示和撤销；当前不应假装已具备航点编辑器 |
| 图层/地理约束 | 有任务、空域、设施、风险图层及高度过滤；筛选控制分散在地图上方/下方 | 官方产品重视场景、数据与平台开放；本次未核验到足够细的图层交互，不臆测 | 任务、地理围栏和集合点可切换显示；地理围栏支持包含/排除区域及返回点 | 任务地图关联上下文数据和支持图层 | 借鉴QGC把空域/限制区作为明确的规划图层；本项目需区分“数据可见”与“规则判定通过” |
| 高度/地形 | 可筛选飞行器高度，UI 有地形参考控件；目前无真实DEM证据 | 官方资料涵盖任务/数据能力，未据此断言当前地图有地形剖面 | 底部可看地形高度剖面；任务统计可展示各航点高度差、距离、坡度等 | 通用GIS任务图层，非本项目要做的飞行高度规划器 | 当前高度筛选可保留；真实地形剖面应在DEM校验后进入P2，先不要显示无来源地形数据 |
| 时间/计划反馈 | 新建任务有窗口；事件/审计记录在操作后显示 | 官方强调任务管理/作业流程，具体时间轴交互未纳入对比 | 计划视图展示任务项及统计，聚焦规划过程 | 任务协同含成员、任务、报告、轨迹等上下文图层 | 增加地图底部任务窗口/限制窗口/告警时间标记；与审计事件列表保持不同语义 |
| 风险反馈 | 风险航段加粗、风险对象红色；解释和证据主要在其他业务结果区 | 运营平台整合管理与分析能力；不推断其风险模型 | 任务项、围栏、地形与航线信息关联，供飞行计划核对 | 任务上下文、轨迹、报告等协作信息 | 风险不只用红色：点选后说明风险类型、来源、时间、关联航段及人工下一步 |
| 保存/状态 | API有任务/检查/路线等动作；截图中测试任务混入正式列表 | 云端任务管理与平台集成 | 计划有打开/保存/上传和未同步状态提示 | 有创建任务过程、任务组与地图配置 | 明确草稿、已保存、检查通过/有风险、待人工确认等状态；演示fixtures与E2E数据隔离 |
| 空间数据/来源 | 显示合成演示声明；离线底图，不含已证实真实DEM/权威空域 | 与DJI设备/服务集成并支持部署形态；与公开参考数据平台不是同类 | 可离线计划并使用地图/地形相关能力（具体数据源依部署配置） | 组织内GIS地图、图层和任务数据 | 所有真实数据逐层登记来源、许可、坐标系、版本、更新时间；公开/合成/实测明确分层 |
| 交互复杂度 | 地图、设施列表、设施管理混在一张卡片；信息密度高且垂直过长 | 功能覆盖面广，适用于运营团队，不适合直接照搬其设备生态 | 工具化、任务导向清楚，但有地面站专业术语和飞行任务门槛 | 角色与团队工作流清晰，但偏GIS任务协作 | 以本项目值守人员的“先读懂、再检查、再处置”作简化，不照搬无人机厂家绑定或通用GIS大而全 |

### 4.2 对比结论

- **最值得借鉴 QGroundControl 的部分**：地图作为规划工作区；路线/航点有明确选择与编辑模式；计划状态可见；航线、地理围栏、集合点等可切换；任务统计与高度剖面靠近地图展示。
- **最值得借鉴 DJI FlightHub 2 的部分**：从单次航线提升到运营任务闭环的产品思路、任务/设备/数据分析的组织方式和开放集成意识。其设备生态和实际云控能力不能被本项目未接入的演示UI冒领。
- **最值得借鉴 ArcGIS Mission 的部分**：地图上的任务上下文与图层/团队任务关联；创建任务时明确地图和上下文数据；任务不是孤立的线段。
- **不建议照搬**：DJI硬件与云控菜单、QGC飞控上传和参数设置、ArcGIS完整组织/Server/Responder体系。本项目当前范围是低空运行基础底座演示，不是飞控地面站、厂商云控或通用GIS协作套件。

## 5. 调整后的信息架构与交互方案

### 5.1 桌面布局（1366×768 / 16:9）

```text
顶部：系统名 / 当前任务 / 数据状态 / 数据边界
┌────────────┬──────────────────────────────┬─────────────────┐
│ 左侧图层栏 │ 任务聚焦二维地图（主工作区） │ 选中对象/任务详情 │
│ 图层开关   │ 主/备/实际/风险航段          │ 状态、高度、时间窗 │
│ 高度过滤   │ 航点/设施/限制区/风险         │ 风险依据/处置入口  │
│ 图例       │ 比例尺、北向、坐标、来源      │ 检查/路线/事件      │
├────────────┴──────────────────────────────┴─────────────────┤
│ 底部：任务窗口、临时限制窗口、告警时间点；全局图例/数据边界     │
└──────────────────────────────────────────────────────────────┘
```

建议地图占横向可用空间约60%–70%；左侧图层宽度约190–220px，右侧详情约300–340px。将设施主数据管理从地图工作区移到独立“设施管理”视图/抽屉；运行地图仅保留设施图层和选中设施摘要。首屏优先展示地图，不让指标卡和纵向管理表单把地图挤出视野。

### 5.2 地图对象层级

1. 主航线：最高视觉优先级，青绿色实线，方向箭头，起终点锚点。
2. 风险航段：只在存在可解释风险结果时突出，用琥珀/红色加粗并关联风险编号；不能根据演示状态随意伪造风险。
3. 备用航线：蓝色虚线，弱于主航线但仍清晰可辨。
4. 实际轨迹：白色细实线；若数据是模拟，图例明确标成“模拟实际轨迹”。
5. 当前飞行器：一个主符号 + 选中详情；仅主任务飞行器默认显示标签，其他对象随缩放等级聚合/按需显示。
6. 空域/限制区：半透明填充与边线使用不同图案/线型；区分参考空域、禁限区、临时管制，图例不得共用一个“参考空域”类别。
7. 设施/风险对象：使用可辨识的不同图标；无标签时可点击，选中后在侧栏显示完整名称，不默认给所有点贴卡片。

### 5.3 标签和点击规则

- 标签优先级：当前选中任务/飞行器 > 风险对象 > 起终点 > 最近相关设施 > 次要设施/区域名称。
- 只为当前选中对象显示完整名称和状态；一般对象用短标签或悬停提示。标签冲突时按优先级自动隐藏/偏移；不能用固定“最多显示N个”替代避让算法。
- 点选对象：地图符号进入明显选中态、侧栏详情同步更新、地图保持当前范围；点空白不清除航线或触发业务动作。
- 平移与选择要区分：空白处拖动平移；图形目标可点击选择；进入路线编辑时才允许选取/拖动航点。退出编辑不应误改草稿。
- 缩放变化：远景对设施/风险聚合，近景显示细节；缩放、拖动、复位后选中对象及路线状态保持稳定。
- 键盘可操作：Tab到地图控件、明确焦点态；对象列表提供地图对象的非地图替代选择方式。

### 5.4 四维数据表达

| 维度 | 地图上直接表达 | 详情/辅助表达 | 必须显示的数据边界 |
|---|---|---|---|
| 空间 | 位置点、区域面、航线和风险段 | 经纬度、坐标系、比例尺、空间数据来源 | 公开参考/合成演示，不代表权威边界 |
| 高度 | 选中飞行器旁显示高度；高度层筛选影响显示对象 | 计划高度、测量/模拟高度字段、相对高度定义 | 没有DEM/高度基准时标明“合成值/未提供” |
| 时间 | 当前任务窗口带、临时管制有效区间、告警事件点 | 数据更新时间、事件详情、窗口时区 | 时间数据来源、更新时间、模拟/真实状态 |
| 状态 | 图标形态 + 颜色 +必要文字/图例 | 电量、链路、任务状态、风险处置状态 | “实时模拟”不能显示成真实在线 |

## 6. 修订后的实施顺序与验收门槛

### Sprint M0：地图工作区重构（P0）

- 将图层控制/图例从地图下方长列表迁入左侧窄栏；地图中央成为首屏核心；任务选择/详情放在右侧。
- 设施主数据增删改移入独立管理视图或弹层，不与运行态势地图混卡。
- 仅保留当前任务关联对象；空态、无任务和数据错误均可解释。
- 隔离演示seed与Playwright测试数据；截图不得出现 `API smoke` 等测试数据。

**验收**：1366×768 首屏同时显示标题、数据边界、地图、图层、选中任务/对象；地图占工作区横向至少60%；首屏不需要页面滚动才能看到主航线与图例。

### Sprint M1：航线层级、标签与选择反馈（P0）

- 统一 SVG 回退和 MapLibre 的符号/颜色/线型语义；非选中航线降权，主线方向箭头可读。
- 加入基于屏幕坐标的标签避让或优先级布局；密集设施按缩放级别聚合。
- 选中飞行器、设施、限制区、风险对象后联动右侧详情；显示数据时间、来源与状态。
- 重新审核“地形参考”控件：无DEM时禁用或准确重命名为合成示意，不得让控件名暗示真实地形接入。

**验收**：预设高密度样例中无重叠标签；路线可区分；点选后有地图高亮和详情；滚轮/按钮缩放、拖动、复位正常；键盘仍可访问控件。

### Sprint M2：时间与运行解释（P1）

- 增加地图内任务窗口时间带，叠加临时限制有效区间和告警发生时刻；点击时间事件定位对应对象/航段。
- 将任务计划时间、事件/审计时间、数据更新时间分开命名和展示。
- 增加比例尺、方向、坐标读数、图层数据状态和来源元信息。
- 让高度展示明确区分“计划高度”“遥测高度/模拟高度”“地形高度”，无字段时不渲染伪值。

**验收**：仅看界面可分辨空间、相对高度、任务/限制时间和运行状态；对过期/缺失数据有显式标识。

### Sprint M3：地理数据与约束（P2，外部数据准入后）

- 对公开底图、DEM、建筑/设施数据完成来源、许可、分辨率、坐标系、时间和覆盖范围登记。
- 先做数据校验与局部样区截图，再启用地形/建筑表达；建筑碰撞与净空计算需可重复的服务端/算法测试，不把渲染结果当安全结论。
- 如需要三维演示，独立接入 Cesium 工作区，二维地图保持 MapLibre，不互相冒充。

**验收**：数据清单和授权说明齐全；缺瓦片/无覆盖时可回退；地形和建筑值可追溯；算法结果含版本、输入约束和风险解释。

## 7. 商业化风格文案建议

- 页面标题：**低空运行态势**；副标题/任务上下文：**当前任务：{任务名称} · {任务状态}**。
- 数据边界常驻文案：**公开参考 / 合成演示数据**。下一行：**当前视图不代表真实授权空域、飞行许可或权威测绘边界**。
- 无真实地形时控件：**地形示意（合成）**，并在详情提供“非DEM数据”。不得仅写“地形参考”。
- 飞行器数据徽标：**模拟运行** / **数据未接入**；仅在真实遥测通道接通并有更新时间时使用“实时”。
- 风险区分：**规则命中 / 需人工确认 / 数据缺失**，不要全部压成含义不明的“告警”。
