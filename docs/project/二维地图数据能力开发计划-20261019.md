# 二维地图数据能力开发计划

**日期**：2026-10-19  
**适用版本**：`recovered-release-20261017`  
**目标**：在现有 MapLibre 运行地图上逐步补齐地点检索、公开地形参考、建筑物信息和路线空间复核能力。所有能力必须可追溯、可降级，并明确数据质量边界。

## 0. 已有基线与边界

### 已有基线

- MapLibre 可加载 OpenFreeMap/OpenMapTiles schema 的在线矢量底图，并保留本地 OSM 参考 GeoJSON 降级路径。
- 已存在梁平范围 OSM 参考要素数据和数据来源标注。
- `backend/terrain.py` 可读取本地演示 DEM 网格并计算简化地形指标；当前网格为合成演示数据，不能称为公开 DEM。
- 已有空间/航线规划数据需求、外部数据资源普查和地图接入记录。
- 当前分支 `recovered-release-20261017` 已推送至 GitHub，远端与本地均为 `af4e0b01da57d6122d8611b8952d15d5821cffd7`；`main` 保持在 `2361d1404013dab2f14ef083c7337acb287a0922`，本轮未改写或覆盖。

### 必须遵守的边界

- OSM 建筑轮廓不等于完整或权威建筑数据；缺失 `height`/`building:levels` 时高度必须显示“未知”。
- DEM 地面高程不包含建筑、树木、线缆等障碍物。公开 DEM 的分辨率、垂直基准、覆盖和时效必须随结果呈现。
- 公开参考或合成演示数据不能生成真实授权空域、真实飞行许可或安全放行结论。
- 未获得主管单位/运营方授权数据前，路线空间校核仅是原型级提示，不得标记“安全可飞”。
- 网络服务要有超时、限频、缓存和可解释错误；不得把浏览器端直接请求第三方服务作为唯一运行路径。

## 1. 阶段与完成门槛

### P0：版本与基线封存

1. 核查分支、提交、工作区和远端引用；不强推、不改写历史。
2. 安全推送当前两个已提交版本到指定远端分支及 `main`；远端不可达时记录错误并保留待办，不虚报完成。
3. 复跑后续开发基线测试，确认干净工作区及运行入口。

**验收**：远端引用若可达必须与本地目标提交一致；测试结果和推送结果分开记录。无法连通属于外部阻断，不影响可独立推进的本地开发。

### P1：地名搜索和路线点位确认

1. 定义地名检索服务接口和统一地点候选结构：名称、类别、坐标、来源、来源链接/归属、精度或边界说明。
2. 增加明确提交式搜索和候选列表；候选由用户选择后才可设为起点、途经点或终点，不做未经选择的自动落点。
3. 点位可查看、调整、移除，并与现有任务航线草稿状态联动；保存、撤销和返回修改行为保持一致。
4. 本轮搜索只索引已下载的梁平 OSM 公开参考要素，不请求外部地理编码服务；远程地址库/地理编码需单独核验服务条款、网络依赖与限频后再扩展。
5. 本地索引未覆盖或地图服务未加载时保留手工坐标输入，并区分“本地数据无匹配”和“本地索引未就绪”。

**验收**：地点候选坐标正确落点；起点/途经点/终点可选择并随任务保存；路由校核按途经点逐段执行；不误覆盖既有任务；键盘与窄屏可操作；搜索来源与署名可见；失败可恢复。

### P2：公开 DEM 接入和高程剖面

1. 初始版本通过平台后端按需代理公开高程 API，不在浏览器直连第三方；设置梁平范围、每次最多 50 个采样点、超时、24 小时缓存和每秒最多一次上游请求。
2. 记录 API 来源、请求/采集时间、输入坐标系、覆盖状态与数据边界。Open-Meteo 官方文档说明其使用 Copernicus DEM 2021 GLO-90，标称 90m 分辨率且要求 Copernicus 署名；接口本身未声明垂直基准，必须继续标为未知，不猜测、不换算 AGL。
3. 按路线和途经点生成定距采样并在前端展示剖面；服务超时/无值时明确失败，不回填离线合成网格。
4. 若需离线现场运行或安全级净空分析，后续另行导入可核验 DEM 栅格，记录产品、分辨率、CRS、垂直基准、许可和校验和；公开在线 API 不能替代该资产。
5. Open-Meteo 官方定价页区分非商业免费使用与商业许可；本次仅接入竞赛演示参考，正式商业部署前必须向服务方核对并取得适用许可（[官方定价](https://open-meteo.com/en/pricing)）。接口响应和剖面 UI 均显示该使用边界。

**验收**：边界外、服务超时、响应结构异常、缓存与点数限制有测试；实时 API 抽样可通；截图可见来源和不确定性。当前只验收为公开高程参考，不得用于净空/安全结论；离线 DEM 尚未完成；Open-Meteo 商业服务许可未取得。

### P3：建筑轮廓与高度属性

1. MapLibre 当前若使用 OpenMapTiles schema 样式，可复用 `building` footprint 与 `building-3d` 挤出图层进行底图展示和点选属性查询；这只是底图参考，不等于本地建筑障碍物数据集。
2. 从可审计的 OSM/Geofabrik 区域数据制作独立梁平建筑参考数据集，记录提取日期、许可/署名、边界、过滤和转换步骤。
3. 统一字段：要素 ID、几何、名称/类型、原始高度、楼层数、估算高度、估算方法、来源、采集时间、质量等级。
4. 只有原始 `height` 可作为来源声明的建筑高度；`render_height` 只用于底图挤出呈现，可能包含样式默认值/估算，不能当作实测值；楼层换算同样要标注假设。缺字段时保留未知。
5. 以按需缩放/任务范围裁剪方式显示建筑轮廓；点选显示属性来源与质量，不铺满低缩放全图。

**验收**：GeoJSON/矢量数据结构、几何合法性、坐标范围、去重、缺失高度比例和署名通过检查；点选和缩放显示符合性能预算；未知高度视觉上不伪装为确定高度。官方 OpenStreetMap 版权说明要求显示署名并说明数据按 ODbL 提供（[版权与署名](https://www.openstreetmap.org/copyright)）。当前已核验独立 Geofabrik/OSM 区域建筑轮廓子集并能展示/点选；但 158 个轮廓原始高度字段均缺失，且在线瓦片抽样也未提供原始高度或楼层数，因此仍不能用于垂直冲突或净空判定。

### P4：路线空间复核与数据质量语义

1. 对任务路线采样并与建筑轮廓进行二维相交/邻近检查；只有高度明确且同一高程基准时才做垂直间隔估算。
2. DEM 地形剖面、建筑碰撞、禁限区域、最大高度/最小离地高度分别给出结果和依据，不混成单一“AI安全分”。
3. 结果分类至少包括“发现冲突”“未发现已知冲突”“数据不足需复核”；不能以缺少数据得出无风险。
4. 提供候选结果详情、风险位置回地图、人工确认/返回修改；仅在当前系统已有可靠撤销机制时沿用，不另造不可追溯的覆盖流程。

**验收**：针对相交、近邻、未知建筑高度、DEM 空洞、错误基准、边界点和无障碍线路构造测试；人工操作结果可追踪；UI 展示输入数据来源和规则版本。

当前数据登记契约：`data/reference/dem.manifest.json` 与 `data/reference/buildings.manifest.json` 必须包含 `verified=true`、`source_url`、`license`、`coverage_bbox`、`acquired_at`、`coordinate_reference`、`data_file`、`sha256`；相对数据文件必须存在、位于登记目录内且 SHA-256 一致才会标记为已核验。该标记只表示数据可追溯，不代表权威性或可飞放行。缺建筑障碍物登记/真实DEM登记时，规则接口必须返回 D-001/D-002 人工复核项；合成演示数据不能形成安全结论。当前 OSM 局部 GeoJSON 只有道路、水系和土地覆盖，不含建筑（见 `docs/recovery/数据质量与来源验收记录-20261017.md`），底图建筑点击也不替代本地数据集。

公开建筑数据已现场核验并形成参考子集：下载 Geofabrik 重庆 `chongqing-latest-free.gpkg.zip`（归档 SHA-256 `8b4d8403...9879ec21`），README 声明数据截至 `2026-10-18T20:25:06Z`、ODbL 1.0；`scripts/extract_osm_buildings.py` 从 33,380 个建筑轮廓中按任务区 bbox 裁出 158 个 MultiPolygon 至 `data/reference/liangping-buildings.geojson`。`buildings.manifest.json` 记录来源、许可、覆盖、文件哈希与字段缺失：158 个轮廓均没有原始高度，故地图可在 zoom≥12 展示和点选公开轮廓，但碰撞/净空仍为数据不足，不得估算或放行。

### P5：全量回归、视觉与发布复核

- 后端单元与 API 测试；前端交互 E2E；在线服务失败/离线降级测试。
- 1366×768、1024×768、390×844 截图验收；核对地图加载、弹层/候选列表、图层、图例、数据声明、空态、错误态和键盘焦点。
- 性能检查：地图对象数量、数据体积、搜索限频、栅格采样请求次数；发现超预算先限制数据范围或分块。
- 更新数据清单、许可署名、运行配置、操作说明、已知限制和发布记录；复核仓库 diff，不清理用户数据。

**总验收**：按本计划逐条列出通过/失败/外部阻断与证据；所有 P0/P1 缺陷关闭；未授权能力或数据不作商业/安全保证。截图和测试不能只由代码字段存在来替代。

## 2. 执行顺序与阻断处理

顺序为 P0 → P1 → P2 → P3 → P4 → P5。每阶段先核对现有接口和工作区，再做最小可验证实现，完成代码检查、自动化测试、浏览器交互和截图检查后才进入下一阶段。

- GitHub 网络阻断：保存完整错误与本地提交号，继续不依赖网络的工作；网络恢复后重试并核对远端提交。
- 公开数据许可、下载或覆盖不满足：保留接口和数据导入契约，标记阶段阻断；不得用合成数据填充“真实”结果。
- 第三方接口不稳定：保留服务端适配层和本地手工操作路径；错误状态和缓存来源须可见。
- 数据精度不足：输出“需复核/不具备判定条件”，不擅自设安全阈值或作放行结论。
- 测试或截图不通过：留在当前阶段修复，不以计划文档、代码静态存在或口头报告代替验收。

### 当前执行切片：路线人工决策闭环

1. 后端仅允许有权限的 admin/dispatcher 做决策；采用/退回/撤销必须验证航线归属和当前状态，原因写入审计；飞行启动只接受当前有效的已采用航线。
2. 前端在候选航线详情展示采用、退回修改、撤销入口；要求填写操作理由，展示决策人、时间、理由和当前状态；决策后刷新任务和地图状态。
3. 增补 API 状态迁移测试与 Playwright 桌面/移动交互验收，包含无权限、重复/非法迁移、撤销后不能起飞、审计可追溯。
4. 完成后继续禁限区域逐段校核，再执行 P5 全量测试、截图、可访问性与性能验收；任何失败留在当前切片修复。

**当前切片结果**：后端决策状态和起飞门禁、前端理由输入/角色显示/决策审计、浏览器回归与桌面/手机截图均已实现；发现并修复了异步时间线重建 DOM 导致按钮事件丢失的问题。最终回归另修复建筑定位缩放级别和并发 E2E 环境竞态。路线几何编辑未包含在本切片，不把“重新生成”表述成“编辑原航线”。计划内地图/数据与路线复核功能以当前演示和公开参考数据边界验收完成；真实建筑高度、离线权威 DEM、未知垂直基准、商业许可及全 WCAG/生产负载审计列为外部或后续正式部署门槛，不以缺失数据生成安全结论。
