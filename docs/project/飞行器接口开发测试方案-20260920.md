# 飞行器接口开发测试方案

## 1. 文档信息

- 项目：梁平县域数字空域与低空运行智能服务平台
- 模块：飞行器接入与运行遥测
- 文档版本：V1.0
- 日期：2026-09-20
- 适用阶段：P1 真实遥测接入开发、接口联调和比赛演示验证
- 数据边界：公开参考 / 合成演示数据；不代表真实授权空域、真实飞行许可或权威测绘边界

## 2. 目标与原则

### 2.1 目标

建立一套可替换、可审计、可回放的飞行器接入能力，使不同飞控、厂商云或边缘网关能够通过统一接口向平台上报：

- 飞行器位置、高度、速度和航向；
- 电量、链路质量和飞行状态；
- 时间戳、数据来源和设备身份；
- 运行异常及任务关联关系。

### 2.2 原则

1. 飞行器只通过边缘网关或适配器接入平台，不直接访问数据库。
2. 所有设备数据先进入统一遥测模型，再进入任务、告警和地图模块。
3. 首期只做只读遥测接入，不通过本平台直接控制飞行器。
4. 所有遥测、告警、人工确认和状态变化必须可追溯。
5. 真实设备联调前，必须先通过模拟器、异常注入和离线回放测试。

## 3. 接入范围

### 3.1 P0/P1 纳入范围

- 飞行器主数据登记；
- 飞行器与任务绑定；
- 边缘网关身份认证；
- HTTP/HTTPS 遥测上报；
- MAVLink 或厂商协议适配器；
- 遥测标准化和字段校验；
- 飞行会话创建与更新；
- 遥测轨迹采样；
- 运行状态更新；
- 低电量、链路下降、失联和暂停告警；
- 地图和飞行器状态卡刷新；
- 断网缓存与补传；
- 审计、回放和测试报告。

### 3.2 暂不纳入范围

- 自动起飞、降落、返航和解锁；
- 自动修改飞控参数；
- 自动执行重规划航线；
- 替代法定审批、空管或监管系统；
- 面向特定行业的任务控制逻辑；
- 真实授权空域的权威判定。

## 4. 总体架构

```text
飞行器 / 飞控
    ↓ MAVLink、厂商 SDK、厂商云
边缘适配器 / Edge Gateway
    ↓ HTTPS 或 MQTT
遥测接入服务
    ↓
统一遥测标准化
    ↓
任务状态、飞行会话、轨迹采样、告警、审计
    ↓
地图态势、飞行器卡片、任务时间线、运行报告
```

### 4.1 模块职责

| 模块 | 职责 | 是否允许控制飞行器 |
|---|---|---|
| 飞行器/飞控 | 产生原始状态和位置数据 | 不由平台直接控制 |
| 协议适配器 | 将不同协议转成统一遥测 | 否 |
| 边缘网关 | 认证、缓存、重连、补传、限流 | 首期否 |
| 遥测接入服务 | 校验、归一化、写入和返回结果 | 否 |
| 运行规则服务 | 告警、状态判断和任务关联 | 否 |
| 前端控制台 | 展示态势、状态、事件和轨迹 | 仅人工处置建议 |

## 5. 当前接口基线

### 5.1 遥测上报接口

```http
POST /api/missions/{mission_id}/telemetry
Content-Type: application/json
```

当前接口由后端 `backend/server.py` 的 `_ingest_telemetry()` 处理，数据标准化位于 `backend/telemetry.py`。

### 5.2 标准遥测请求体

```json
{
  "longitude": 107.758,
  "latitude": 30.646,
  "altitude": 120,
  "speed": 12.5,
  "heading": 90,
  "battery": 86,
  "link_quality": 92,
  "status": "airborne",
  "timestamp": "2026-09-20T08:30:00Z",
  "source": "mavlink-gateway"
}
```

### 5.3 字段约束

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| longitude | number | 是 | 105–110 |
| latitude | number | 是 | 28–32 |
| altitude | number | 是 | 0–1200 米 |
| speed | number | 否 | 0–150 |
| heading | number | 否 | 0–360 |
| battery | number | 是 | 0–100 |
| link_quality | number | 否 | 0–100 |
| status | string | 否 | ready/airborne/paused/completed/lost_link/landed |
| timestamp | string | 否 | ISO-8601；缺省使用服务端时间 |
| source | string | 否 | 数据来源标识 |

### 5.4 返回结果

成功时返回：

```json
{
  "session_id": 12,
  "mission_id": "MS-20260915-001",
  "status": "running",
  "telemetry": {
    "longitude": 107.758,
    "latitude": 30.646,
    "altitude": 120,
    "battery": 86,
    "link": "online",
    "status": "airborne",
    "source": "mavlink-gateway",
    "timestamp": "2026-09-20T08:30:00+00:00"
  }
}
```

错误返回必须包含：

```json
{
  "code": "INVALID_TELEMETRY",
  "message": "battery 超出允许范围"
}
```

## 6. 开发任务拆分

### F1：设备与接入主数据

- 增加设备接入登记字段；
- 增加网关编号、设备序列号和来源类型；
- 增加设备接入状态；
- 增加设备最后在线时间；
- 增加设备与任务绑定校验；
- 增加停用设备禁止上报规则。

### F2：边缘适配器

- 实现 `SimulatorAdapter`；
- 实现 `MavlinkAdapter` 接口骨架；
- 实现厂商适配器抽象接口；
- 统一转换为标准遥测 JSON；
- 添加本地缓存队列；
- 添加指数退避重连；
- 添加批量补传和顺序号。

### F3：平台遥测服务

- 校验设备身份；
- 校验任务与飞行器绑定关系；
- 校验时间戳和数据顺序；
- 支持重复数据幂等处理；
- 写入 `flight_sessions`；
- 写入 `telemetry_samples`；
- 更新 `vehicles` 和 `missions`；
- 写入事件和审计日志。

### F4：运行告警

- 低电量告警；
- 链路质量下降告警；
- 失联超时告警；
- 高度异常告警；
- 偏航告警；
- 遥测超时告警；
- 重复告警抑制；
- 告警恢复和人工处置。

### F5：前端联动

- 飞行器位置刷新；
- 当前高度和状态更新；
- 电量和链路指标刷新；
- 地图轨迹增量更新；
- 告警中心更新；
- 任务时间线更新；
- 数据来源和时间戳展示；
- 数据延迟和离线状态提示。

## 7. 测试环境

### 7.1 环境分层

| 环境 | 数据 | 目的 |
|---|---|---|
| 单元测试环境 | 构造 JSON | 字段和规则验证 |

### 7.2 测试数据集

至少准备：

- 正常直线飞行轨迹；
- 高度逐步变化轨迹；
- 低电量轨迹；
- 链路质量下降轨迹；
- 失联后恢复轨迹；
- 暂停和继续轨迹；

- 断网缓存后批量补传数据。

## 8. 测试分类与用例

### 8.1 接口契约测试

| 编号 | 场景 | 期望结果 |
|---|---|---|
| API-001 | 完整合法遥测 | 200/成功，创建或更新飞行会话 |
| API-002 | 缺少 longitude | 422，返回 `INVALID_TELEMETRY` |
| API-003 | 经度超出 105–110 | 422，拒绝写入 |
| API-004 | 纬度超出 28–32 | 422，拒绝写入 |
| API-005 | 高度小于 0 或大于 1200 | 422，拒绝写入 |
| API-006 | 电量小于 0 或大于 100 | 422，拒绝写入 |
| API-007 | 非法状态值 | 422，返回 `INVALID_STATUS` |
| API-008 | 非法时间戳 | 422，返回 `INVALID_TIMESTAMP` |
| API-009 | mission_id 不存在 | 404，返回 `MISSION_NOT_FOUND` |
| API-010 | 未认证请求 | 401/403，拒绝接入 |
| API-011 | 已停用飞行器上报 | 403，拒绝写入 |
| API-012 | 任务与飞行器不匹配 | 409，拒绝写入 |

### 8.2 幂等与顺序测试

| 编号 | 场景 | 期望结果 |
|---|---|---|
| IDEMP-001 | 同一条遥测重复提交 | 不重复生成轨迹采样或告警 |
| IDEMP-002 | sequence 重复 | 返回已处理或幂等成功 |
| IDEMP-003 | 时间戳倒退 | 拒绝或标记乱序，不覆盖最新状态 |
| IDEMP-004 | 设备重连后补传 | 按顺序写入轨迹 |
| IDEMP-005 | 同一设备并发上报 | 不出现状态回退 |

### 8.3 状态机测试

| 起始状态 | 输入 | 目标状态 |
|---|---|---|
| ready | airborne | running |
| running | paused | paused |
| paused | airborne | running |
| running | lost_link | offline/需处置 |
| running | landed | completed |
| running | completed | completed |
| completed | airborne | 按产品策略拒绝或新建会话 |

### 8.4 告警测试

| 编号 | 条件 | 期望结果 |
|---|---|---|
| ALT-001 | battery = 20 | 生成低电量告警 |
| ALT-002 | battery = 19 | 生成严重低电量告警 |
| ALT-003 | link_quality < 30 | 生成链路下降告警 |
| ALT-004 | status = lost_link | 生成失联告警 |
| ALT-005 | status = paused | 生成需人工确认事件 |
| ALT-006 | 同一告警连续上报 | 只保留一个开放事件 |
| ALT-007 | 指标恢复正常 | 记录恢复或允许人工关闭 |

### 8.5 前端联动测试

- 遥测更新后地图飞行器位置发生变化；
- 高度、电量、链路和状态卡同步变化；
- 轨迹线新增采样点；
- 低电量时显示低电量状态；
- 失联时显示失联状态；
- 告警中心出现对应告警；
- 任务时间线出现遥测记录；
- 数据来源显示为设备或网关；
- 遥测时间超过阈值时显示数据延迟；
- 页面刷新后最新状态仍能恢复。

### 8.6 安全测试

- 无认证请求测试；
- 错误设备密钥测试；
- 设备越权上报其他任务测试；
- 重放旧遥测测试；
- 超大 JSON 请求测试；
- 高频请求限流测试；
- 非法字段注入测试；
- 日志脱敏测试；
- 设备停用后继续上报测试；
- 网关证书过期测试。

### 8.7 断网与恢复测试

1. 平台在线、网关在线，持续上报 10 分钟。
2. 切断网关到平台的网络 5 分钟。
3. 网关继续接收并缓存遥测。
4. 恢复网络连接。
5. 网关按顺序补传缓存数据。
6. 平台检查轨迹连续性、重复数据和状态最终一致性。

验收要求：

- 不丢失关键遥测；
- 不生成重复轨迹；
- 不因补传旧数据覆盖最新状态；
- 恢复后告警状态最终一致；
- 审计记录保留补传来源。

### 8.8 性能测试

初始目标：

- 单设备上报频率：1–2 秒/条；
- 100 台设备并发上报：接口错误率小于 1%；
- P95 接口响应时间：小于 500ms；
- 单设备 24 小时轨迹持续写入无明显内存增长；
- 前端状态刷新延迟：正常网络下小于 3 秒；
- 告警生成延迟：遥测入库后小于 2 秒；
- 补传期间平台服务不崩溃。

性能测试必须区分：

- 单设备长稳；
- 多设备并发；
- 高频突发；
- 断网恢复补传；
- 前端多页面同时订阅。

## 9. 联调步骤

### 第一步：模拟器联调

- 使用 `SimulatorAdapter` 发送正常轨迹；
- 验证接口响应、数据库写入和地图更新；
- 验证任务状态和飞行器卡片。

### 第二步：异常注入

- 注入低电量、低链路和失联；
- 验证告警、人工确认和审计；
- 验证恢复后的状态回归。

### 第三步：边缘网关联调

- 验证设备认证；
- 验证本地缓存；
- 验证断线重连；
- 验证批量补传；
- 验证序列号和时间戳。

### 第四步：飞控协议联调

- 接入飞控回放数据；
- 对照原始数据和标准化数据；
- 检查经纬度、高度、电量和状态映射；
- 检查丢包、乱序和重复包。

### 第五步：小规模真实设备静态测试

- 设备不上电飞行，仅验证链路和遥测；
- 验证设备身份与任务绑定；
- 验证位置和状态变化；
- 验证断网恢复；
- 完成安全审批后再进入低风险试飞。

## 11. 验收标准

### 必须通过

- 合法遥测可以写入并更新地图；
- 非法遥测被拒绝且不污染数据库；
- 任务不存在、设备停用和任务不匹配会被阻断；
- 低电量、链路下降和失联告警准确；
- 重复、乱序和补传数据处理符合预期；
- 飞行轨迹可以回放和导出；
- 页面刷新后状态可以恢复；
- 接入全程有来源和审计记录；
- 只读接入不会触发飞控动作；
- 无明显未处理异常和数据丢失。

### 暂不作为本阶段通过条件

- 自动控制飞行器；
- 自动修改飞控参数；
- 自动执行重规划航线；
- 替代法定审批或空管系统。

## 12. 开发完成定义

本方案对应功能只有在以下条件同时满足时，才能标记为“飞行器接口接入完成”：

1. 接口契约测试全部通过；
2. 模拟器、异常注入和断网补传通过；
3. 设备认证和任务绑定通过；
4. 地图、告警、轨迹和审计链路完整；
5. 性能目标达到当前阶段基线；
6. 真实设备静态联调通过；
7. 输出完整测试报告和证据包；
8. 明确标注公开参考 / 合成演示数据边界。
