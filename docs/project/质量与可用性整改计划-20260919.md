# 梁平低空运行平台质量与可用性整改计划

制定日期：2026-09-19  
适用范围：前端控制台、模拟运行闭环、地图交互、导出与 E2E 验证

## 一、整改目标

本轮不扩展新的行业场景，不增加农业、应急、物流适配，也不增加真实飞控能力。目标是把当前“代码门禁通过、用户体验部分不通过”的状态，推进到：

1. 竞赛演示路径可连续完成；
2. P0 交互阻断全部关闭；
3. P1 可用性问题显著收敛；
4. 核心 E2E 与地图 E2E 可稳定重复运行；
5. 所有演示数据、权限和能力边界表达一致；
6. 每轮开发结束都有可追溯的质量证据。

## 二、当前基线

### 已通过

- Python 单测 53/53；
- 前端静态检查、类型检查、构建通过；
- OSS 检查通过，生产依赖无高危漏洞；
- 发布检查通过；
- 模拟飞行、暂停/继续/结束、轨迹回放、GeoJSON/CSV 导出专项通过。

### 当前阻断

- 核心全量 E2E 在 Windows 服务生命周期或 Playwright 产物阶段不稳定；
- 任务详情存在“无开放告警但仍显示查看待处置告警”的死按钮风险；
- 告警入口可能重复展示同一事件；
- 权限不足时部分入口静默隐藏；
- 地图无障碍语义树可能暴露过多底图对象；
- 飞行器卡片业务状态表达不完整；
- 版本号与环境文案存在不一致风险；
- 非法审计筛选参数缺少稳定的 422 错误响应。

## 三、整改优先级

### P0：先修复演示阻断

#### P0-1 任务主路径修复

目标：任何任务详情都必须有正确的下一步动作。

工作内容：

- 根据任务状态、规则检查结果和开放告警动态生成主按钮；
- 无开放告警时禁止显示“查看待处置告警”；
- 主按钮统一支持进行中、成功、失败三态；
- 错误状态必须说明原因和下一步处理方式；
- 增加任务主路径 E2E：计划→检查→航线→启动→异常→重规划→确认。

验收标准：

- 不存在无效主按钮；
- 每个任务状态至少有一个可解释动作；
- 主路径连续执行 10 次无阻断。

#### P0-2 权限与演示路径统一

目标：比赛演示人员能明确知道当前角色和可执行范围。

工作内容：

- 顶部显示当前角色、运行环境和数据边界；
- 权限不足时不静默隐藏，改为显示禁用入口和权限说明；
- 固定演示账号、初始化密码和独立演示数据库；
- observer 角色完成只读验证；
- admin/dispatcher 完成任务、航线和设施工作台验证。

验收标准：

- 登录失败有可执行的恢复提示；
- 不同角色入口和按钮状态一致；
- 竞赛演示脚本不依赖手工改数据库。

#### P0-3 全量 E2E 生命周期稳定化

目标：避免“代码通过但测试进程卡住或产物竞态”。

工作内容：

- 修复 `global-setup.cjs` 的端口清理竞态；
- 核心 E2E 与地图 E2E 使用互不干扰的数据库和端口；
- 每轮测试显式记录服务 PID、端口、数据库路径和日志文件；
- 禁止多个 Playwright 进程并行清理同一端口；
- trace、screenshot 和 report 使用独立目录；
- 增加测试结束后的进程树清理和孤儿进程检查。

验收标准：

- 核心 E2E 连续运行 3 次均完成；
- 地图 E2E 连续运行 3 次均完成；
- 失败时能从服务日志定位原因；
- 不再出现 trace 文件 `ENOENT` 或旧数据库污染。

### P1：提升前端可用性

#### P1-1 告警单一入口与处置反馈

- 合并顶部优先告警和告警中心的重复动作；
- 处置前显示告警、影响任务和风险等级；
- 处置后显示操作者、时间、备注和成功提示；
- 事件筛选与任务详情同步；
- 处置结果刷新地图、任务状态和时间线。

#### P1-2 地图无障碍和信息降噪

- 底图道路与参考要素默认 `aria-hidden`；
- 只暴露空域、设施、飞行器、航线、风险对象；
- 地图增加图层摘要和坐标获取提示；
- 键盘用户可以访问图层控制和业务对象；
- 验证 1366×768 下标签、图例和时间轴可读。

#### P1-3 飞行器状态卡完善

- 增加链路状态、任务状态、告警状态；
- 电量使用颜色+文字双编码；
- 增加“查看详情”按钮和当前可执行动作；
- 低电量、失联、需确认状态需要显式说明。

#### P1-4 版本与环境标识统一

- 页面标题、顶部版本、追溯条和页脚全部读取同一运行时元数据；
- 明确显示“演示环境 / 封闭试点 / 生产环境”；
- 明确显示“公开参考 / 合成演示数据”；
- 禁止出现过期 Sprint 或不一致版本号。

#### P1-5 前端输入校验

- 经度纬度范围就地校验；
- 时间窗口先后关系就地校验；
- 任务编号重复提示；
- 高度范围和单位提示；
- 错误信息关联到具体字段，不只依赖全局提示。

### P2：工程质量增强

- 审计日志前端查询面板；
- 审计动作、操作者、对象和时间范围筛选；
- 非法 `limit`、无效状态和未知筛选参数统一返回 422；
- 导出按钮增加下载成功/失败反馈；
- 轨迹导出增加采样数量和数据来源摘要；
- 增加报告导出内容的字段级测试；
- 增加长时间刷新和重复操作测试。

## 四、执行顺序

### 阶段 1：P0 根因修复

1. 修复任务主按钮和告警空状态；
2. 统一权限与演示环境；
3. 稳定 Playwright 生命周期；
4. 跑核心主路径专项测试。

### 阶段 2：P1 用户体验整改

1. 告警入口合并与处置反馈；
2. 地图无障碍降噪；
3. 飞行器状态卡完善；
4. 版本、环境和数据边界统一；
5. 表单就地校验。

### 阶段 3：P2 工程收口

1. 审计日志查询面板；
2. 导出反馈和字段级校验；
3. 重复操作、长时间刷新、异常网络测试；
4. 更新质量报告和比赛演示脚本。

## 五、每轮必跑门禁

```powershell
python -m unittest discover -s tests -q
powershell -ExecutionPolicy Bypass -File scripts/frontend-static-check.ps1
npm run typecheck:frontend
npm run build:frontend
npm run check:oss
powershell -ExecutionPolicy Bypass -File scripts/release-check.ps1
npm run test:e2e
npm run test:e2e:map
```

额外要求：

- 核心 E2E 和地图 E2E 分开运行；
- 至少各连续运行 3 次；
- 保存服务日志、测试报告、trace 和截图；
- 任何“卡住、超时、旧进程污染、数据库残留”都视为质量问题；
- 不以单次成功作为稳定性结论。

## 六、完成定义

本轮整改只有同时满足以下条件才算完成：

1. P0 问题全部关闭；
2. P1 问题有明确证据证明已关闭或降级；
3. 核心与地图 E2E 各连续 3 次通过；
4. 竞赛演示主路径连续 10 次完成；
5. 1366×768 截图中地图、图例、状态和时间轴清晰可读；
6. 无新增高危依赖问题；
7. 版本、权限、数据边界和报告内容一致；
8. 最终报告区分竞赛演示、封闭试点和正式商业交付，不夸大能力。

## 七、阻断处理

| 阻断 | 处理方式 |
|---|---|
| 全量 E2E 卡住 | 先隔离端口和数据库，再拆分专项用例；不扩大业务改动 |
| 真实账号不可用 | 使用独立演示数据库和明确演示账号，不修改生产凭据 |
| 地图无障碍树过大 | 优先隐藏底图辅助节点，只保留业务对象语义 |
| 设计改动影响既有选择器 | 保留现有 `data-*`、ID 和 API 契约，采用增量改造 |
| 导出接口参数异常 | 统一错误码和 422 响应，增加正负例测试 |
| 时间不足 | 优先关闭 P0，再做 P1，P2 只做不影响主路径的增强 |
