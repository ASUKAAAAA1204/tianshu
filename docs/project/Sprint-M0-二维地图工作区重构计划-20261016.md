# Sprint M0：二维地图工作区重构计划

日期：2026-10-16  
基线：恢复项目当前 MapLibre 运行链路（版本标记 `0.6.0-recovered`）  
目标文档：[二维地图板块目标与成熟产品对比及调整方案](./二维地图板块目标与成熟产品对比及调整方案-20261016.md)

## 对标标注说明

以下每项改动均标注来源。**DJI FlightHub 2** 代表无人机运营管理/任务闭环参考；**QGroundControl (QGC)** 代表地图任务规划与地图工具工作流参考；**ArcGIS Mission** 代表地图任务上下文与协作信息组织参考。`本项目质量约束` 表示由当前代码、数据边界、竞赛演示或安全要求导出的要求，不是声称对标产品具有相同实现。标注表示设计启发来源，不表示复制其代码或宣称本项目已拥有其能力。

## 1. Sprint 目标

把现有“地图卡片 + 任务列表 + 地图下方图层/设施/设施管理长内容”的页面，改造成首屏可工作的二维地图工作区：地图成为主工作区，图层控制轻量固定，任务/对象上下文可见，设施主数据管理不再挤占运行地图；在干净的演示数据上，可通过 1366×768 实际截图和交互测试验收。（对标/参考项目：QGC 的地图主工作区和任务信息组织；ArcGIS Mission 的地图任务上下文；首屏占比与截图验收属于本项目质量约束。）

Sprint 只重构信息架构、布局、基础对象选择/视图状态接线和演示数据隔离。此 Sprint 不增加地图时间轴，不重做标签避让算法，不接入真实DEM/建筑，不实现3D、AI路径规划或真实飞行器控制。

## 2. 现状与改造理由

- `frontend/index.html` 的 `.workspace` 当前为地图面板和任务面板两列；地图面板内部还纵向承载图层、设施状态、设施主数据表单和管理列表。
- `frontend/styles.css` 现有地图画布高度受卡片布局约束；首屏还显示指标卡，地图横向空间有限。
- `frontend/app.js` 同时渲染 `#layerList`、`#facilityList`、`#facilityForm`、`#facilityAdminList` 和任务列表，且选中任务默认由运行中/首个任务决定，不具备清晰的用户选中状态模型。
- 1366×768 `test-results/maplibre-1366x768.png` 中，地图面积不足，航线主体偏小；设施/风险 callout 靠近路线；右侧存在重复 `B3B4 API smoke` 任务，演示数据被测试副作用污染。
- MapLibre / SVG 地图适配器、任务详情/检查/航线动作、设施 CRUD、层筛选、高度筛选和数据边界声明均属于已有合同；重构须保留，不应通过删控件绕开问题。

## 3. 目标布局

### 3.1 桌面首屏

```text
┌──────────────────────────────────────────────────────────────┐
│ 标题 / 当前任务摘要 / 演示与数据边界状态                      │
├────────────┬──────────────────────────────┬─────────────────┤
│ 图层与筛选 │                              │ 任务/对象详情     │
│ 约200px    │ 主地图 60%–70% 工作区宽度    │ 约320px          │
│ 图例       │ 主/备/实际路线、相关对象      │ 任务动作、状态     │
│ 高度筛选   │                              │ 设施状态摘要      │
│ 地图控件   │                              │                  │
├────────────┴──────────────────────────────┴─────────────────┤
│ 地图图例与数据边界（首屏可见）；地图画布目标高度≥420px         │
└──────────────────────────────────────────────────────────────┘
```

首屏的实际高度以浏览器 viewport 为准；地图不应因页面顶部指标卡而被压到折叠线以下。建议 M0 将四张全局指标收成一条紧凑状态带或移至非地图首页区域，不能让地图低于首屏核心区域。（对标/参考项目：QGC 以计划地图作为 Plan View 主体；指标压缩及首屏尺寸门槛属于本项目质量约束。）

### 3.2 窄屏与响应式

- 1366px 及以上：三栏，图层栏 + 主地图 + 详情栏。（对标/参考项目：QGC 的地图与计划工具分区；三栏尺寸是本项目布局决策。）
- 900px–1365px：图层栏收为窄侧栏/可折叠，地图仍是主列，详情栏允许折叠。（对标/参考项目：本项目响应式质量约束；不声称来自特定竞品。）
- 900px 以下：单列；默认地图与当前任务摘要在前，图层/详情通过可访问的折叠区展开；禁止横向溢出。（对标/参考项目：本项目响应式与无障碍质量约束。）
- 地图画布按可用高度自适应，不能为满足桌面固定高度导致移动端内容被遮挡。（对标/参考项目：本项目质量约束。）

## 4. 功能需求与用户流程

### 4.1 首屏默认状态

1. 使用明确的当前任务选中状态；若只有一个任务则自动选中并显示自动选择原因，若多个任务则保持上次选择或按明确规则选择，并允许用户更改。（对标/参考项目：DJI FlightHub 2 的运营任务管理定位、ArcGIS Mission 的任务上下文；自动选择规则为本项目交互设计。）
2. 地图 fit 至该任务航线和相关对象的 bounds；无任务时显示可操作空态，不显示伪路线。（对标/参考项目：QGC Plan View 的计划聚焦工作流；空态真实性是本项目质量约束。）
3. 左侧只展示已发布且可用图层、图层含义、开关与对象数/状态；高度过滤作为飞行器筛选，不伪装成完整3D层控。（对标/参考项目：QGC 的任务/地理围栏/集合点图层切换；数据发布状态及高度边界是本项目约束。）
4. 地图下方持续显示紧凑图例和“公开参考 / 合成演示数据”边界声明。（对标/参考项目：本项目数据可信与演示边界要求，非竞品功能映射。）
5. 右侧显示选中任务的编号、名称、飞行器、状态、计划高度/时间窗（数据缺失则显示“未提供”），以及既有详情/检查/航线等动作入口。（对标/参考项目：DJI FlightHub 2 的运营任务上下文；QGC 任务信息邻近地图的组织方式；字段缺失策略是本项目数据约束。）

### 4.2 地图交互

- 保留 MapLibre 原生平移/滚轮缩放、缩放按钮、复位、任务聚焦、图层开关和高度筛选。（对标/参考项目：QGC 的地图导航/地图工具交互；MapLibre 与SVG双适配是本项目现有架构约束。）
- 点击右侧任务卡切换地图聚焦对象；地图选中状态与任务列表/详情同步。（对标/参考项目：DJI FlightHub 2 的运营任务上下文；ArcGIS Mission 的地图任务关联。）
- 点击地图飞行器/空间对象时更新选中对象详情，不触发任务写操作。（对标/参考项目：QGC 的对象/航点选择反馈；不触发写操作属于本项目安全约束。）
- 图层变更只影响显示，不改变后台规则判定、任务数据或图层源数据。（对标/参考项目：本项目功能边界与质量约束，非竞品功能映射。）
- MapLibre 初始化失败时保留现有 SVG 回退；布局不能假设只有 MapLibre DOM。（对标/参考项目：本项目恢复基线和兼容性约束。）
- 数据来源提示和公开/合成边界必须在地图首屏可见，不可被详情滚动区隐藏。（对标/参考项目：本项目数据可信要求，非竞品功能映射。）

### 4.3 设施管理迁移

- 移出运行地图的设施主数据表单与 CRUD 列表，迁至独立“设施管理”区域/视图；M0 可实现为独立页签或独立对话框，但入口必须明确、可键盘访问。（对标/参考项目：DJI FlightHub 2 按运营任务与管理能力分区的产品定位；具体独立页签/弹窗属于本项目IA决策。）
- 运行地图仍可显示设施图层、选中设施摘要和只读设施状态列表；不在地图右侧编辑设施坐标。（对标/参考项目：ArcGIS Mission 的地图上下文承载任务信息；查看与维护分离属于本项目职责边界。）
- 设施新增、更新、停用的 API、校验、权限检查和审计逻辑保持原样；迁移只改变入口/容器，不改变业务语义。（对标/参考项目：本项目既有合同与回归质量要求，非竞品功能映射。）
- 退出管理视图后回到原地图范围、选中任务和图层状态；管理操作成功后刷新设施数据。（对标/参考项目：QGC 计划编辑保持任务状态的工作流启发；具体状态恢复属于本项目交互质量要求。）

### 4.4 演示/测试数据隔离

- 定位重复 `API smoke` 任务来源，分别标记：生产代码缺陷、开发环境残留、Playwright fixture 或 smoke 脚本写入。不得靠名称过滤隐藏真实数据。（对标/参考项目：本项目演示真实性与测试质量约束，非竞品功能映射。）
- E2E 使用独立临时数据库/独立数据目录或 API mock；禁止复用用户的持久化 `data/platform.db` 或 `data/demo-runtime.db` 执行创建任务测试。（对标/参考项目：本项目数据保护与测试隔离约束。）
- 演示数据集使用固定 fixture，启动/重置行为可重复；重置必须显式作用于专用 demo DB，不触碰用户本地持久数据。（对标/参考项目：本项目演示可复现与数据保护约束。）
- 截图测试启动前验证数据集版本/预期记录数；出现 smoke/E2E 测试前缀即失败，不截图验收。（对标/参考项目：本项目截图验收质量门槛。）
- 不删除当前数据库里的记录。本 Sprint 先识别归属并在隔离环境重跑验证，再决定是否提供安全的人工清理流程。（对标/参考项目：本项目数据保护约束。）

## 6. 重要技术决策与实现约束

1. **地图状态只能有一个真源。** `app.js` 保存被选任务、对象与数据；适配器负责绘制和交互事件，不各自维护冲突的任务选择。SVG fallback 和 MapLibre 都消费同一上下文。（对标/参考项目：本项目现有双地图适配器架构与状态一致性质量约束。）
2. **重构采用兼容式DOM迁移。** 先列出 `#mapCanvas`、`#layerList`、`#facilityForm`、`#facilityAdminList`、`#missionList`、`#mapObjectSummary` 等调用点和测试选择器；每移动/改名一个节点，同步更新消费者或保留稳定 id，不做大范围一次性重命名。（对标/参考项目：本项目现有前端/API合同与回归约束。）
3. **地图布局不用绝对定位拼整页。** 使用 CSS Grid/Flex 限定列宽；地图容器显式 `min-width:0`，canvas/viewport 有确定高度；MapLibre resize 在容器尺寸变化后调用并验证。（对标/参考项目：MapLibre 官方容器/渲染要求及本项目响应式质量约束。）
4. **现有任务动作不内嵌至地图图层交互。** 检查、航线生成、启动/事件动作继续通过既有API和确认流程；点地图对象仅选择，不触发高风险写操作。（对标/参考项目：QGC 的地图选择/计划编辑分工启发；安全边界为本项目约束。）
5. **管理设施与查看设施分离。** 运行地图轻量只读；维护工作流进管理区域。设施 CRUD 的后端权限、审计、校验保持不变。（对标/参考项目：DJI FlightHub 2 管理/运营能力分区的产品思路；本项目设施权限和审计合同。）
6. **禁用误导文案。** 若 M0 暂时保留 DEM 控件，只能准确说明“合成地形示意/演示数据”；更合适是本 Sprint 隐藏或禁用该控件并标注待接入，真实DEM接入属于 P2。（对标/参考项目：本项目数据溯源与不夸大能力约束。）
7. **不要用截图像素作为唯一测试。** 自动化断言 DOM/交互/控制台错误/API写入；截图核实真实地图大小、文字和对象可读性；两类证据都要有。（对标/参考项目：本项目商业化验收质量约束。）

## 8. 验收门槛 / Definition of Done

以下条件必须全部满足才可关闭 Sprint M0：

1. MapLibre 和 SVG fallback 都能进入重构后的地图工作区；没有因DOM迁移造成已有API合同改变。（对标/参考项目：本项目现有双引擎和API兼容约束。）
2. 1366×768 默认态满足标题、合成数据边界、图层、地图、路线图例、当前任务/对象详情同屏；地图占主工作区至少60%横向宽度。（对标/参考项目：QGC 地图主工作区启发；尺寸和边界要求属于本项目。）
3. 任务、设施状态、图层控制、设施主数据管理职责分开；设施CRUD既有测试全部通过。（对标/参考项目：DJI FlightHub 2 管理/运行能力分区思路；CRUD保持是本项目合同。）
4. 任务选择、地图聚焦、图层开关、高度筛选、地图平移/缩放/复位、地图对象选择和回退均有自动化交互断言。（对标/参考项目：QGC 地图/规划交互；自动化覆盖是本项目质量门槛。）
5. 桌面、平板、手机视口截图无横向滚动、按钮覆盖、文字裁切、地图空白或测试数据混入。（对标/参考项目：本项目响应式与商业截图验收约束。）
6. 两次从干净专用测试数据启动均得到同一数据集；用户本地DB未被测试污染或破坏。（对标/参考项目：本项目数据保护和演示复现约束。）
7. 测试、启动命令、截图路径和已知剩余问题形成记录；没有通过只改文案或隐藏模块来规避失败。（对标/参考项目：本项目发布质量门槛。）

## 9. 风险与阻断处理

| 风险/阻断 | 处理方式 | 停止条件 | 对标/参考项目 |
|---|---|---|---|
| 当前数据库含重复测试任务，无法确认归属 | 备份式只读盘点；创建独立fixture DB；不自动删除/改写现有记录 | 只有必须改动用户持久DB才能继续时暂停并请求确认 | 本项目数据保护约束，非竞品功能 |
| MapLibre canvas resize后黑屏/偏移 | 每个断点调整后调用 resize，等待渲染事件并做实际截图；失败回退SVG | 两种引擎都无法显示有效地图时不验收 | MapLibre 官方运行要求及本项目双引擎回退架构 |
| 现有选择器被E2E/API流程依赖 | 先盘点合同，逐个更新测试和DOM消费者，兼容id保留一轮 | 关键现有任务闭环回归失败时不迁移下一块 | 本项目现有前端/API合同，非竞品功能 |
| 设施管理入口迁移影响CRUD | 只搬容器和前端入口；后端不改；CRUD成功/失败/取消全部回归 | 设施写操作/权限审计出现差异即回滚本次前端迁移 | DJI FlightHub 2 管理/运营分区思路；本项目既有CRUD/审计合同 |
| 三栏桌面方案在小屏失效 | 小屏采用折叠/单列，不强行三栏缩小 | 任一支持视口出现横向溢出或不可达控件，DoD不通过 | 本项目响应式质量约束，非竞品能力对标 |
| 测试数据隔离需修改启动方式 | 仅对专用测试运行配置加临时数据目录；演示/用户数据库默认行为不变 | 无法证明测试不写用户DB时不执行写型E2E | 本项目数据保护约束，非竞品功能 |
